Introducción

Este API esta docoumentado en formato OpenAPI desarrollado por el equipo de desarrollo de Crediviva. Para esta documentación, puedes utilizar el api key special-key para probar los filtros de autorización.

Información de Autenticación

Crediviva ofrece la siguiente forma de autenticación:

  • API Key
  • Bearer JWT Token

bearerHttpAuthentication

JWT Token en el header Authorization, el cual concede de la autenticación necesaria para consumir los recursos expuestos que requieren autenticación.

Security Scheme Type: HTTP
HTTP Authorization Scheme: Bearer

defaultApiKey

API-Key proporcionada por Crediviva, la cual concede la autenticación necesaria para consumir los recursos expuestos que requieren autenticación.

Security Scheme Type: API Key
Header parameter name: X-API-Key

ApiKeyAuth

API-Key proporcionada por Crediviva, la cual concede la autenticación necesaria para consumir los recursos expuestos. Cada proveedor (Chattigo, Twilio, etc.) recibe una API Key única.

Security Scheme Type: API Key
Header parameter name: X-API-Key

BearerAuth

Token JWT obtenido del endpoint de autenticación de clientes. Requerido para acceder a los servicios de documentos.

Security Scheme Type: HTTP
HTTP Authorization Scheme: bearer
Bearer format: JWT

Endpoints para verificar y autenticar clientes de WhatsApp.

Verificar si teléfono está registrado

Verifica si un número de teléfono está registrado en el sistema y determina el tipo de autenticación requerida.

Reglas de Validación:

  • Teléfono debe tener formato exacto: +507XXXXXXXX
  • Prefijo +507 es OBLIGATORIO seguido de exactamente 8 dígitos
  • NO se acepta ningún otro formato (sin espacios, guiones, paréntesis)
Authorizations:
ApiKeyAuth
query Parameters
phone
required
string^\+507[0-9]{8}$
Examples:
  • phone=+50769442422 - Formato exacto válido
  • phone=+50712345678 - Otro número válido
  • phone=+50787654321 - Tercer ejemplo válido

Número de teléfono con formato exacto requerido:

  • OBLIGATORIO: +507 seguido de exactamente 8 dígitos

Autenticar cliente

Autentica un cliente usando diferentes niveles de información según su estado de registro.

Escenarios:

  • Tipo 1 (Registrado): teléfono + cédula + fecha nacimiento
  • Tipo 2 (No registrado): Debe PRIMERO completar flujo OTP, luego teléfono + cédula + fecha nacimiento + email

Flujo Completo Tipo 2:

  1. POST /otp/request → Solicitar OTP con cédula
  2. POST /otp/verify → Verificar OTP y obtener tempToken
  3. GET /authenticate → Autenticación completa con todos los datos

Reglas de Matching:

  • Coincidencia 100% exacta requerida
  • Todos los campos tienen el mismo peso
  • 3-5 intentos fallidos → pausa de 10 minutos

Formato de Cédulas:

  • Ingresar exactamente como aparece en el documento físico
  • Incluir guiones, puntos, letras según corresponda al documento
  • Ejemplos: 8-123-456, PE-1-234-567, 1-234-567, E-8-12345
  • NO modificar el formato del documento original
Authorizations:
ApiKeyAuth
query Parameters
phone
required
string^\+507[0-9]{8}$
Example: phone=+50769442422
